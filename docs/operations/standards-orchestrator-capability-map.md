# Standards Orchestrator Capability Map

## Outcome

One canonical repository compiles product-specific requirements, documents, gates, evidence, and Zeref execution metadata from one project manifest.

## Capability domains

| Domain | Human standards | Machine policy | Templates | Skills or services | Verification |
|---|---|---|---|---|---|
| Universal governance | Active | Active | Active | Context and conflict services | Repository checks |
| Product strategy and research | Foundation | Planned expansion | Product brief and records | Intake and needs skills | Scenario benchmarks |
| UX and UI | Active foundation | Profile-driven | Flow and handoff | Heuristic and state reviews | Design QA |
| Accessibility | Existing baseline plus overlays | Profile-driven | Requirements and evidence | Accessibility review | Manual and automated evidence |
| Design systems and Figma | Active foundation | Planned token schema | Token and component artifacts | Token review | Parity and visual checks |
| Architecture | Existing baseline plus layering | ADR policy | ADR and implementation plan | Boundary review | Architecture and contract tests |
| Frontend | Active foundation plus stack overlays | Profile-driven | Client plan | Client review | Unit through end-to-end tests |
| API and integration | Active foundation | Contract-driven | API artifacts | Contract review | Schema and contract tests |
| Backend and data | Active foundation | Data profile | Data and migration artifacts | Data review | Migration, restore, and authorization tests |
| Security and red team | Active foundation | Risk profile | Threat and finding records | Threat and abuse review | Evidence-backed validation |
| Legal and privacy | Source-governed foundation | Applicability vocabulary | Legal status and privacy artifacts | Legal routing | Source and escalation checks |
| AI and agents | Existing AI Operations plus product standard | Active | Evaluation and tool records | AI routing and evaluation | Gold and adversarial benchmarks |
| Cloud and cost | Active foundation | Risk and budget profiles | SLO, runbook, cost model | Reliability and cost review | Load, failure, and cost evidence |
| Git and delivery | Existing plus consolidated operations | Active | PR and release evidence | Delivery review | Exact-head CI and release evidence |

## Status rule

`Active foundation` means the structure and baseline rules exist. It does not mean every jurisdiction, industry, language, framework, platform, or provider overlay is complete. Missing coverage must remain visible as planned, insufficient facts, source review required, or not verified.
