# Migrating 0.5.x Project Manifests

Grimoire now validates project manifests before creating any compiled output.
The command remains available. The current compiler emits fifteen generated
filenames, including control trace, conflict, and exclusion evidence.

## Supported manifest contract

The root must be a JSON object. These fields remain required:

- `schema_version`
- `project`
- `risk`
- `standards`
- `zeref`

The optional 0.5.x fields remain available:

- `$schema`
- `users`
- `markets`
- `platforms`
- `stack`
- `data`
- `ai`
- `unknowns`

Unknown root and nested properties are rejected. Values must use their declared
JSON types. `project.product_types` must contain at least one item. Other
optional arrays may remain empty.

The active supported standards version comes from
`policies/standards-orchestrator.json` and its matching declaration in
`policies/baseline.json`. It is currently `0.4.0`; the repository release
version `0.5.0` is not a project-manifest standards pin.

## Bounded values

- Project names: 1 to 200 characters
- Taxonomy items and Zeref cost ceilings: 1 to 128 characters
- Declared unknowns: 1 to 2,048 characters
- Arrays: at most 64 items
- Manifest files: at most 1 MiB

Text containing Unicode control characters (`Cc`) is rejected. Unicode format
characters (`Cf`) remain structurally valid; their display and context-rendering
policy is outside this migration. Diagnostics report only the machine code,
JSON path, expected constraint, and actual type. Input values are not echoed.

## Controlled failures

Invalid manifests exit with code `2`, do not create the output directory, and
write a stable JSON error to standard error:

```json
{
  "status": "INVALID",
  "error_code": "GRIM_MANIFEST_INVALID",
  "issues": [
    {
      "code": "type_mismatch",
      "path": "$.risk",
      "expected": "object",
      "actual": "string"
    }
  ]
}
```

Issues are sorted by path and code. A valid manifest produces
`MANIFEST_VALIDATION_STATUS=PASS`; broader project readiness and release
assurance remain independently `NOT_VERIFIED` without their own evidence.
