# Migrating Grimoire 0.5.x to 1.0

## Outcome

The 1.0 migration preserves established entrypoints while replacing
generation-only success with evidence-aware orchestration. Existing valid 0.5.x
project manifests can compile into the fifteen-file pack without being
rewritten to an invented version.

## Version boundary

The repository release version and standards policy version are separate:

- repository release version: `0.5.x` moving to `1.0.0`;
- standards policy version accepted by project manifests: `0.4.0`;
- structural `schema_version`: integer `1`.

Do not change `standards.version` to `1.0.0`. The 1.0 repository release
continues to accept policy version `0.4.0` until a separate policy migration is
reviewed and implemented.

## Required migration

1. Pin a reviewed Grimoire release or exact commit.
2. Run `python3 scripts/grimoire.py status --json`.
3. Validate and compile the existing manifest with `project boot`.
4. Replace single-field readiness assumptions with the eight status dimensions.
5. Read `pack_generation_status` only for generation success.
6. Treat `NOT_VERIFIED` as missing evidence, not as `PASS` or `BLOCKED`.
7. Verify the compiled pack independently with `project verify`.
8. Review `CONTROL_TRACE.json`, `CONFLICT_REPORT.json`, and `EXCLUSIONS.json`.
9. Preserve explicit approval for merge, publication, deployment, credentials,
   destructive actions, and release.

## Pack changes

The project boot command remains available. The current pack contains fifteen
files. In addition to the original outputs, consumers must retain and review:

- `CONTROL_TRACE.json`
- `CONFLICT_REPORT.json`
- `EXCLUSIONS.json`

Do not discard unexpected files to make verification pass. Recompile into a
clean destination and investigate drift.

## Status changes

The aggregate status is conservative. Pack generation cannot raise project
readiness, release assurance, legal review, or Zeref execution. Automated
`COMPLIANT` is not accepted.

## Deprecated identity alias

`--engineering-standards-commit` remains a compatibility alias for
`--grimoire-commit` through the 0.5.x migration window. New commands and
artifacts must use Grimoire naming. The alias remains covered by
`tests/test_grimoire_identity.py`.

## Verification

```bash
python3 scripts/verify_documented_commands.py --json
python3 scripts/grimoire.py check
```

Valid 0.5.x fixtures, strict manifest failures, status mapping, pack integrity,
and the deprecated alias are tested in the repository suite. A failure exits
with a controlled diagnostic; it must not be converted to a successful
migration claim.

## Rollback

Keep the prior pinned Grimoire version and compiled pack until the new pack is
reviewed. Roll back by restoring the prior version pin and prior generated pack
through the consuming repository’s normal reviewed change process. Do not
rewrite history or delete evidence.
