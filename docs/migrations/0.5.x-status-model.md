# Migrating 0.5.x Status Consumers

Grimoire 0.5.x emitted a single `status` that primarily described whether the
compiler produced a pack. Grimoire 1.0 hardening separates that result from
broader assurance.

## Compatible surfaces

The project boot command and all twelve generated filenames are unchanged.
`PROJECT_STATUS.json` and `EXECUTION_RECEIPT.json` still contain a top-level
`status`.

## Changed semantics

The top-level `status` is now the conservative aggregate of eight required
dimensions. Read `EXECUTION_RECEIPT.pack_generation_status` when the only
question is whether pack generation completed.

Example:

```json
{
  "status": "NOT_VERIFIED",
  "pack_generation_status": "PASS"
}
```

This means the pack was generated, but project readiness, release assurance, or
another required dimension still lacks evidence. It is not a failure of pack
generation.

## Legacy mapping

When importing an old dimensionless value:

| 0.5.x value | Conservative aggregate |
|---|---|
| `PASS` | `NOT_VERIFIED` |
| `PARTIAL` | `NOT_VERIFIED` |
| `NOT_VERIFIED` | `NOT_VERIFIED` |
| `BLOCKED` | `BLOCKED` |

No missing evidence is inferred during migration. Automated `COMPLIANT` is not
accepted as a completion or legal-review status.
