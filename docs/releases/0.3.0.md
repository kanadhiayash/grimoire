# Grimoire 0.3.0

Release date: 2026-07-23

## Purpose

Version 0.3.0 turns Grimoire into an operational control plane that is readable by humans and directly consumable by AI agents across coding harnesses, browser projects, and ordinary browser chats.

Zeref Memory Engine remains unchanged. Grimoire owns activation portability, source-pack compilation, repository navigation, and verification. Zeref continues to own its runtime, memory, agents, skills, permissions, and boot contract.

## Included capabilities

- Unified dependency-free Python CLI for status, catalog, checks, source packs, and harness adapters.
- Machine-readable repository index and schema.
- Operational root `AGENTS.md` with boot order, task routing, precedence, boundaries, and completion requirements.
- Cross-surface Zeref activation states and truthful runtime-versus-simulation reporting.
- Browser source packs for ChatGPT Projects, Claude Projects, Gemini Gems, and generic browser chats.
- Pinned source provenance, SHA-256 integrity records, freshness limits, and staged browser memory.
- Managed global activation fragments for Claude Code, Codex, and Gemini CLI.
- Local and CI conformance checks using the same operational command surface.

## Version model

The repository release and policy modules use independent semantic versions:

| Component | Version | Meaning |
|---|---:|---|
| Grimoire repository | 0.3.0 | Complete operational repository release |
| Baseline policy | 0.3.0 | Repository-level policy composition |
| AI Operations policy module | 0.2.0 | Stable command, autonomy, approval, memory, and lifecycle contract |
| Surface Activation policy module | 0.3.0 | Cross-harness and browser-surface activation contract |

A component policy version may be older than the repository release when its behavior is unchanged. A component version may not exceed the repository version, and the baseline must declare the exact version of each component it composes.

## Compatibility

This is a backward-compatible minor release for existing 0.2.0 consumers.

Existing consumers may continue using the AI Operations 0.2.0 paths and semantics. Adoption of the new repository index, unified CLI, surface-activation policy, browser source packs, and harness installer is explicit.

No existing Zeref runtime contract is replaced or modified.

## Migration

### Repository consumers

1. Pin Grimoire `0.3.0` or the reviewed release commit.
2. Keep the repository-local `AGENTS.md`, `.standards/manifest.json`, and `docs/standards-exceptions.md` contract.
3. Add `policies/surface-activation.json` only when the project uses cross-surface Zeref activation.
4. Run:

```bash
python3 scripts/grimoire.py status --json
python3 scripts/grimoire.py check
```

### Local AI harnesses

Review the plan before applying managed global blocks:

```bash
python3 scripts/grimoire.py harness detect
python3 scripts/grimoire.py harness plan
python3 scripts/grimoire.py harness apply
python3 scripts/grimoire.py harness verify
```

### Browser projects and chats

Compile a source pack using pinned Grimoire and Zeref commit SHAs, upload the complete pack, and copy the generated provider instructions into the project instruction field.

Browser source-backed operation must report `PROJECT_SIMULATION` or `CHAT_SIMULATION`. It must not claim that the local Zeref runtime or canonical memory writer executed.

## Verification gate

The release is valid only when the release branch passes:

```bash
python3 scripts/grimoire.py check
```

The GitHub Actions Grimoire CI result is the repository-level source of truth for the release PR.

## Deferred work

The following remain outside 0.3.0:

- Signed source-pack manifests.
- Connector-backed automatic source refresh.
- Remote cross-surface writeback service.
- Authenticated local Zeref runtime gateway.
- Automatic reconciliation of state held by multiple browser surfaces.
