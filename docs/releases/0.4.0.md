# Release 0.4.0: Standards Orchestrator Foundation

## Outcome

Version 0.4.0 upgrades the repository into a neutral Grimoire control plane prepared for the Standards Orchestrator name. It remains one repository and compiles one bounded pack from one project manifest.

## Added capabilities

- Twelve-file project context pack and SHA-256 execution receipt
- Structured standards and document contracts
- Product design, heuristic, accessibility handoff, Figma and token, architecture, frontend, API, backend and data, security, cloud and cost, AI and agent, Git delivery, legal, and execution standards
- Assumption, decision, risk, product, flow, implementation, and release templates
- Neutral global instructions and private Yash surface-specific copy-paste pack
- Skill and service catalogs, capability map, legal source foundation, and scenario benchmarks
- ADR-0005 through ADR-0008
- Persistent CI conformance artifact

## One-call workflow

```bash
python3 scripts/grimoire.py project boot \
  --manifest .standards/project.json \
  --output .standards/compiled
```

The primary human and AI read is `.standards/compiled/AI_CONTEXT.md`. Structured outputs support Zeref routing, gates, acceptance, evidence, and status.

## Zeref boundary

Standards Orchestrator defines requirements, expected outcomes, documents, gates, evidence, costs, and limits. Zeref owns activation, roles, model and tool routing, skills, approvals, retries, memory, and execution receipts. Zeref Memory Engine is not modified by this release.

## Compatibility

Version 0.4.0 retains 0.3.0 AI Operations, cross-surface activation, browser source packs, harness adapters, repository index, and CLI behavior. Projects may adopt `.standards/project.json` incrementally.

## Migration

1. Pin version 0.4.0 or its reviewed commit.
2. Copy `templates/project/project.json` to `.standards/project.json`.
3. Replace example values with verified project facts.
4. Compile the pack.
5. Review unknowns, required documents, gates, acceptance, and Zeref execution profile.
6. Record project exceptions locally.
7. Do not represent a generated pack as a new canonical policy source.

## Coverage status

The release establishes detailed baseline domains and explicit expansion points. It does not claim every jurisdiction, industry, language, framework, platform, cloud provider, trend, or regulation is complete. Missing coverage remains visible as planned, insufficient facts, source review required, or not verified.

## Legal status

The legal registry is a source-governed foundation, not legal advice and not exhaustive. Automated output may classify applicability and evidence but cannot certify compliance.

## Verification gate

The release is valid only when the exact PR head passes:

```bash
python3 scripts/grimoire.py check
```

The retained CI report is the repository-level evidence source.
