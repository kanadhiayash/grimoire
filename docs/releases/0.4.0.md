# Release 0.4.0: Standards Orchestrator Foundation

## Outcome

Version 0.4.0 upgrades the repository from an engineering and AI-operations control plane into a neutral Product Engineering Standards and Operations foundation prepared for the Standards Orchestrator name.

## Added

- One canonical repository architecture
- One project manifest and one compiled context pack
- Twelve deterministic output artifacts with integrity receipt
- Structured standard and document contracts
- Product-design, legal, naming, priority, engineering, and Zeref integration standards
- Neutral global instruction modules
- Private Yash instruction overlay excluded from neutral packs
- Legal source authority and freshness governance
- Minimum Correct Change execution discipline
- Tests, checks, benchmarks, and release evidence

## Compatibility

The release is backward compatible with version 0.3.0 command and adapter behavior. Consuming projects may adopt `.standards/project.json` incrementally.

## Migration

1. Pin version 0.4.0.
2. Copy `templates/project/project.json` to `.standards/project.json`.
3. Replace example facts with verified project facts.
4. Run `python3 scripts/standards.py project boot --manifest .standards/project.json --output .standards/compiled`.
5. Review unknowns, documents, gates, and the Zeref execution profile.
6. Do not commit generated packs unless the project policy requires a reviewed snapshot.

## Legal status

The legal source registry is a foundation and is explicitly not exhaustive. It supports applicability routing and evidence but does not provide legal advice or automated compliance certification.
