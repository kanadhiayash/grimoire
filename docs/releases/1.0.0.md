# Grimoire 1.0.0 Release Candidate

**Status: NOT RELEASED**

This document describes the intended 1.0.0 release contract. It does not prove
that a tag, GitHub release, signature, package, deployment, or repository
visibility change exists.

## Candidate capabilities

- strict manifest models and deterministic controlled diagnostics;
- multidimensional completion status with conservative aggregation;
- applicability resolution, control traces, conflicts, and exclusions;
- deterministic fifteen-file project compilation and independent verification;
- versioned standards, sources, crosswalks, predicates, and conformance checks;
- executable benchmark suites, strict-500 validation, and 10,000-case fuzzing;
- Zeref profile and receipt contracts with an explicit external-runtime boundary;
- supported Ubuntu and macOS CI across Python 3.11, 3.12, and 3.13;
- exact-commit release evidence and non-mutating rollback rehearsal.

## Compatibility

The repository release version and standards policy version are independent.
Valid 0.5.x manifests remain supported with standards policy `0.4.0`. The
deprecated browser-pack identity alias remains available during the documented
migration window.

## Assurance state

Release assurance is `NOT_VERIFIED` until every release hard gate passes on the
exact final commit and the owner supplies the fresh exact-commit approval
required by the release issue. Identity signature status is also
`NOT_VERIFIED`. SHA-256 artifact integrity is not an identity signature.

Zeref contract reproduction has independent evidence, but actual external Zeref
runtime execution remains `NOT_VERIFIED` without an approved trust anchor.
Windows runtime support remains `NOT_VERIFIED`.

No overall score or 10/10 claim is made by this document.

## Verification

The final release operation must record exact source, benchmark, environment,
artifact, approval, CI, rollback, and post-release evidence. Until that
operation completes, use the checked-in `VERSION` value as the repository
version.
