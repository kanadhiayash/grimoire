# Grimoire 1.0.0 Release

**Status: RELEASED**

This document describes the 1.0.0 source release contract. It does not claim
that a GitHub Release object, package publication, deployment, repository
visibility change, or cryptographic identity signature exists.

## Candidate capabilities

- strict manifest models and deterministic controlled diagnostics;
- multidimensional completion status with conservative aggregation;
- applicability resolution, control traces, conflicts, and exclusions;
- deterministic fifteen-file project compilation and independent verification;
- versioned standards, sources, crosswalks, predicates, and conformance checks;
- executable benchmark suites, strict-500 validation, and 10,000-case fuzzing;
- Shiroe-compatible profile, receipt, and trust contracts with an explicit external-runtime boundary;
- supported Ubuntu and macOS CI across Python 3.11, 3.12, and 3.13;
- exact-commit release evidence and non-mutating rollback rehearsal.

## Compatibility

The repository release version and standards policy version are independent.
Valid 0.5.x manifests remain supported with standards policy `0.4.0`. The
deprecated browser-pack identity alias remains available during the documented
migration window.

## Assurance state

Release assurance is `PASS` when every release hard gate passes on the exact
final commit and the owner supplies fresh exact-commit approval evidence. The
private-release assurance marker is not a cryptographic identity signature.
SHA-256 artifact integrity is not an identity signature.

The current source-release hard gates are:

- bounded gold-scenario quality metrics;
- measured release-target scale resource budgets;
- pinned public Shiroe source trust contract.

These boundaries cannot be converted to `PASS` by documentation, self-scoring,
or a repository-local contract test.

The final preflight is non-mutating. It reports eligibility from exact-commit
candidate evidence, release evidence, version files, freshness, and approval;
it does not create tags, releases, deployments, packages, or signatures.

Shiroe contract trust is pinned to `kanadhiayash/shiroe` commit
`a4549e06d3a4b398fb2476039026eda49501176a`. Windows runtime support remains
`NOT_VERIFIED`.

No overall score or 10/10 claim is made by this document.
