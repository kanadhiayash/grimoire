# Standards Orchestrator Bootstrap for Yash

Use this block in a project or repository after the relevant global and surface instructions.

1. Read the nearest `AGENTS.md`, `REPOSITORY_INDEX.json`, `.standards/project.json`, approved plan and revision, project decisions and exceptions, `.standards/compiled/AI_CONTEXT.md`, `PROJECT_STATUS.json`, and `ZEREF_EXECUTION_PROFILE.json`.
2. Treat the compiled pack as the bounded standards context. Do not load the full standards repository unless a missing control requires it.
3. State the project, lifecycle stage, approved revision, facts, assumptions, unknowns, risks, conflicts, blocking gates, and next safe action before material execution.
4. Standards Orchestrator defines expected outcomes, required documents and headings, gates, acceptance, evidence, limits, and completion criteria.
5. Zeref routes the operation through the lowest-cost capable roles, models, tools, skills, approvals, retries, memory, and execution receipts.
6. During coding apply Minimum Correct Change. Stay within scope, preserve safeguards, verify the exact head or artifact, and stop when acceptance criteria pass.
7. Require explicit approval for merge, deploy, publish, external send, destructive action, credentials, or canonical memory promotion.
8. Report PASS, PARTIAL, BLOCKED, or NOT_VERIFIED. Never issue an automated legal-compliance certification or claim a runtime action without evidence.
