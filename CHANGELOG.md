# Changelog

All notable changes to Grimoire are recorded here.

The format follows Keep a Changelog principles. Versions follow Semantic Versioning.

## [0.5.0] - 2026-07-27

### Added

- Grimoire repository identity, canonical URL, descriptor, migration guide, and release record.
- Primary `scripts/grimoire.py` command entrypoint and repository-wide identity checks.
- Backward-compatible browser-pack, CLI-flag, and harness-marker migration support.

### Changed

- Prompts, instructions, policies, schemas, adapters, templates, CI labels, doctor output, and metadata now use Grimoire.
- Repository and baseline release versions advanced to 0.5.0.

### Compatibility

- Existing 0.4.0 project and browser packs remain readable during the 0.5.x migration window.
- Zeref Memory Engine remains a separate, unchanged runtime.

## [0.4.0] - 2026-07-24

### Added

- Standards Orchestrator architecture with one canonical repository, one project manifest, and one compiled context pack.
- Dependency-free `project boot` compiler producing twelve human and machine artifacts with SHA-256 receipt.
- Schemas for project manifests, standard records, document requirements, Zeref execution profiles, and Orchestrator policy.
- Detailed standards for authoring, naming, priority, product design, heuristics, Figma and tokens, architecture layering, frontend, APIs, backend and data, security and red team, cloud and cost, AI and agents, Git delivery, legal control, Minimum Correct Change, and Zeref integration.
- Product, flow, implementation, release, assumption, decision, risk, standard, document, and project templates.
- Neutral global instruction modules and a tested eight-file private Yash copy-paste pack.
- Skill and service catalogs, capability map, legal source registry, benchmark specification, and ADR-0005 through ADR-0008.
- Standards Orchestrator checker, instruction-boundary tests, compiler tests, personal-instruction budget tests, and persistent CI reports.

### Changed

- Repository identity is neutral and prepared for a future Standards Orchestrator rename.
- Root agent contract, README, governance, index, baseline policy, CLI, CI, and release documentation integrate Orchestrator behavior while retaining existing AI Operations and cross-surface activation.
- Legal automation reports applicability and evidence status but cannot issue final compliance certification.

### Compatibility

- Existing 0.3.0 AI Operations, surface activation, browser source packs, harness adapters, and command behavior remain supported.
- The project manifest is JSON to preserve the Python standard-library-only runtime.
- Personal instructions are excluded from neutral packs unless explicitly selected.

## [0.3.0] - 2026-07-23

### Added

- Cross-surface Zeref activation policy and JSON schema.
- Explicit local runtime, browser project simulation, browser chat simulation, instruction-only, unavailable, and unverified states.
- Activation, verification, writeback, and external-action receipts.
- Browser source-pack compiler and verifier with pinned source commits, SHA-256 integrity, tamper, freshness, and runtime-claim checks.
- ChatGPT Project, Claude Project, Gemini Gem, generic browser-chat, Claude Code, Codex, and Gemini CLI adapters.
- Safe harness installer with planning, backups, idempotent blocks, verification, and uninstall.
- Surface capability matrix, browser-pack standard, repository index, unified CLI, quickstart, agent entrypoint, tests, release notes, and migration guidance.

### Changed

- Baseline and doctor checks gained surface activation and component-version validation.
- Agent, adapter, README, Make, CI, governance, and reporting contracts became operational and cross-surface.

### Reconciled

- Retained canonical AI Operations layout while preserving locked workflow semantics, source precedence, approval invalidation, currentness, behavior cases, and `NOT_VERIFIED` vocabulary.
